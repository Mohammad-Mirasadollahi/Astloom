# Systemd

Path: `backend/deployments/systemd`

## Purpose

Boot integration for Astloom local/server hosts. Units are **generated by the CLI**, not checked in as static host-specific files.

## Operator commands

```bash
# System unit (needs root to write /etc/systemd/system)
sudo "$(command -v astloom)" boot enable
sudo "$(command -v astloom)" boot disable

# User unit (no root; enable linger for true headless boot)
astloom boot enable --user
loginctl enable-linger "$USER"
astloom boot disable --user
```

The unit is oneshot + `RemainAfterExit` and calls:

- `ExecStart=…/astloom service start` — Compose `postgres`/`neo4j` + MCP HTTP daemon
- `ExecStop=…/astloom service stop`

Day-to-day process control (without changing boot policy):

```bash
astloom service start
astloom service status
astloom service restart
astloom service stop
```

## Modular Boundary

This directory is part of the Astloom backend modular architecture. Host unit files are written at enable-time under `/etc/systemd/system/astloom.service` or `~/.config/systemd/user/astloom.service`.
